# IDOR Sweep — Phase 11

Generated by walking the route table and, for every mutating action, reading the
method body for an authorization decision. Reproduced continuously by
`tests/Feature/IdorSweepTest.php`, which fails if a new mutating route appears
with no gate.

**113 mutating routes. 111 carry an authorization
decision. 2 do not, both vendor-registered and justified below.**

## What counts as a decision

| Decision | Meaning |
|---|---|
| `authorize()` | The action calls `$this->authorize(...)`, resolving a policy or gate |
| `Gate::` | The action consults the gate directly |
| `middleware:auth` | Any signed-in user may reach it, and the action scopes by ownership or a policy further in |
| `middleware:admin` | The `admin` or `super-admin` role |
| `middleware:auth:sanctum` | A valid, unexpired API token |
| `middleware:guest` | Asserts nobody is signed in — the inverse decision, used by login and password reset |

`middleware: auth` on its own is **not** a decision for a route holding another
user's record. That combination is the shape of every IDOR this application has
had, and it is why the sweep also reads each action's body rather than trusting
the route listing.

## The two routes with no decision

| Route | Why it is acceptable |
|---|---|
| `boost.browser-logs` | Laravel Boost development tooling. Not application code; absent in production. |
| `storage.local.upload` | Laravel's local-disk temporary upload. Requires `?upload=1` **and** a valid `X-Disk-Signature` issued by `Storage::temporaryUploadUrl()`, so it is not an open write. Verified the signature check is the first guard in `ReceiveFile::hasValidSignature()`. |

## Findings raised by the sweep

1. **No application mutating route is unguarded.** Every one is covered by a
   middleware gate or an in-action policy check.
2. **No controller gates on a bare role slug.** Asserted by
   `test_no_controller_action_authorizes_with_a_bare_role_slug`. Phase 10 had
   three on the dashboard; the reference-data and report controllers added since
   use `user.manage` and `report.view` instead.
3. **The API is token-only.** `sanctum.guard` was `['web']`, which made Sanctum
   check the *session* guard before the bearer token — so a browser cookie
   authenticated an API route with no token at all. Changed to `[]`.
